# 存檔完整性與防作弊

## 信任邊界

`app/api/save/route.ts` 的一般整包存檔必須經過 `app/save-integrity.ts`，以資料庫目前的存檔、伺服器時間和操作紀錄驗證變動；不能拿客戶端送來的欄位當作授權依據。

這是既有客戶端結算架構的第一階段防護，**不是完整伺服器權威戰鬥**。戰鬥與隨機掉落仍在客戶端；低於允許上限的偽造收益、假擊殺與合法區間內的假裝備仍可能通過。後续應將這些結果改由伺服器產生，以操作 ID、版本與交易防止重放。不能以混淆前端、localStorage 加密、瀏覽器內密鑰或偵測 DevTools 取代權威結算。

## 已加入的檢查

- 首次角色存檔只能由 `/api/character` 的伺服器初始角色建立；一般存檔不接受第一次直接注入。
- 資源、經驗、等級、輪迴與戰力只接受非負安全整數；經驗依目前成長公式檢查。
- 保存伺服器核發且會被消耗的收益額度，包含金幣、經驗、材料、擊殺、物品、世界首領傷害、寶石、打孔石與元寶。額度來源為伺服器經過的時間，最多補計 90 秒，未使用的普通額度最多保留 30 秒；同時重送不能刷新額度。這些是為相容既有玩法設定的寬鬆上限，不代表每筆收益都已驗證真實戰鬥。
- 離線收益只憑伺服器核發且尚未消耗的領取 ID 和秒數取得額度；客戶端時間不能增加可領時數。
- 元寶增量必須來自既有伺服器郵件，或在時間額度內、每個新擊殺／消耗的個人首領票券最多一顆的原有掉落。線上獎勵、每日獎勵和商城交易仍沿用服務端動作。
- 每日獵殺領取只讀雲端已存入的台北當日擊殺數。請求送來的擊殺數不能自行提高領獎進度。
- 輪迴須有服務端技能操作核發的紀錄、Lv.100、第九地圖 30 層，且符合重置內容；只能增加一轉與三點天賦。相容舊版超過五轉的上限正規化。
- 地圖只允許順序解鎖；新地圖必須先通關前圖。最佳樓層增量也消耗擊殺額度。
- 新裝備 ID 不得重複；舊版離線批次已有的 ID 碰撞保留既有份數，不能新增重複。新掉落與溢出郵件改用遞增的安全整數 ID 避免碰撞。新裝備的原始戰力須符合掉落或尋寶祝福範圍；既有裝備不能改原始戰力與身分。強化增量須有最低資源成本；變更的詞綴受品質數量、合法屬性／單位與數值上限限制；洗鍊、打孔由伺服器動作核發，整包存檔不能自改既有詞綴、洗鍊計數或孔數。
- 裝備出售、金幣購買材料、禮包、既有郵件領取、個人首領獎勵保留正常的資源兌換；這些仍不是伺服器隨機結果。
- 郵件 ID 不得重複；已領取資源不能重新開啟領取。寶石含背包與鑲嵌的三進位等價總量一起計算，避免移動位置造成重複認列；增加會消耗獨立額度。

## 拒絕與紀錄

驗證失敗回傳 `409 save_integrity_rejected`，不寫入 `game_saves`。拒絕原因寫入服務端日誌與既有 `gm_action_logs`，每帳號每分鐘最多一筆持久紀錄，操作者為 `system`。紀錄失敗仍拒絕存檔。

GM 工作台的「異常存檔」可查閱上述持久紀錄。新紀錄另保存選定資源／進度欄位的雲端原值與提交值，以及物品、郵件、寶石背包的筆數差異；不保存完整存檔、密碼或 session。裝備內容與同筆數的替換不一定顯示欄位差異。舊紀錄維持只顯示原因，不能補回歷史提交內容。

前端停止戰鬥與自動存檔，保留登入，以遊戲內讀檔重新同步；每次進入角色最多自動恢復一次，再次失敗提供「重新同步」手動操作，避免強制重整與循環退出。讀檔失敗維持停止存檔，不能讓初始值覆蓋雲端。既有 session、版本樂觀鎖、技能授權、管理員資源版本與防重複領取機制仍有效；並行寫入失敗後重新取得雲端版本再驗證，不能用舊額度覆蓋新額度。

本次不自動停權、不清洗既有玩家、不回溯修改已污染存檔。已寫入的異常資源／排行需人工確認帳號與最後正常快照後再處理。保留既有 GM 修改與快照能力，未新增資料表。

## 驗證

`tests/save-integrity.test.mjs` 覆蓋暴增資源／等級／輪迴／戰力、偽造伺服器額度、裝備與詞綴、重複郵件、離線領取、寶石重放、地圖進度，以及正常升級、強化、分解、材料購買、禮包、首領獎勵、品質祝福與舊版經驗／輪迴相容。部署前執行完整 `npm test`、型別與相關檔案 lint；這些不等同登入真實玩家帳號的手動驗收。

## 欄位型別與結構（2026-10-03）

一般存檔在重置、正規化或資料庫寫入前檢查已使用的數值、文字、布林與巢狀結構。名稱不能是物件／陣列；裝備、詞綴、郵件獎勵、穿著 ID、寶石庫與日誌需符合型別。拒絕危险物件鍵及過深結構；原有整包 240 KB 限制保留。缺少舊版選填欄位與字串型舊郵件 ID 相容。欄位錯誤回傳 409 save_integrity_rejected，提供 field 並記錄 GM 異常原因；不把錯誤值轉成文字或零後寫入。排行榜、玩家列表、快照預覽及存檔讀取使用只讀安全投影，避免舊畸形標量值令頁面崩潰；不因此改寫原始雲端資料。型別檢查不能取代消耗驗證或戰鬥權威。

### 新帳號空值相容修正

尚未領取離線收益時，客戶端正常提交 `_lastIdleClaimId: null`。此欄位允許 null、缺省或文字，不能將正常空值判為畸形存檔；仍拒絕數字、布林、物件、陣列。型別拒絕的 GM 紀錄新增 `field`，方便區分誤擋與實際錯誤。登入原子交易與持久限流保留。

### 裝備與巢狀欄位補強

技能配置的 ranks、三個 activeSlots、昇華五個 choices、selectionOpen 等巢狀欄位各自驗證型別；孔位數限制 0～2。GM 異常紀錄詳細資料顯示 field。兩套穿著須符合唯一 ID、裝備歸屬及單部位一件，舊配置讀取會安全整理。洗鍊與打孔的資源扣款、操作重送與並行寫入見 EQUIPMENT.md，沒有將其他客戶端隨機戰鬥／掉落改為完整伺服器權威。

### 正常玩法誤擋修正

- 尋寶祝福升至傳奇上限時，品質仍為傳奇且原始戰力加 38；驗證同時涵蓋本品質區間加 38 與前一品質升級区間加 38，超出仍拒絕。
- `begin_rebirth` 在同一技能操作 CAS 中提交技能重置、進度重置、三點天賦及資源版本。客戶端暫停戰鬥／普通存檔，待雲端重置讀取完成後恢復，第一場戰鬥的經驗與掉落可正常存檔。
- 舊版輪迴已授權但尚未完成進度重置時，僅憑雲端授權標記、昇華紀錄、100 等與第九圖通關證據恢復；先建立 `rebirth_recovery` 快照，再以版本及有效 session 條件写入。重送不重複發點；未授權的存檔不修改。
- `_lastRebirthRevision` 只由伺服器保存；較舊的整包存檔要求重新讀取，不能復活上一輪裝備／地圖。
- 兩套穿著在讀取與提交時移除無效引用；掉落分解同步解除兩套引用。舊視窗原封提交雲端已存在的無效配裝可安全整理，新增非法配裝仍拒絕，不刪背包裝備。
- `tests/save-false-positives.test.mjs` 覆蓋輪迴第一擊／升級／掉落、授權舊檔一次性恢復、舊版覆蓋、滿品質祝福上界、舊配裝，以及同步流程契約；保留原有偽造值拒絕測試。

同一有效 session 與 client 的重複／較舊 sequence 只回覆 `already_applied`，不帶重新套用的 save，不重設戰鬥；拒絕写入的行為保留。新輪迴版本界線與其他真正的資料分歧仍帶雲端存檔重新同步。

掛機秒數由伺服器實際經過時間累積，領取先結算最後一次存檔以後的秒數；時間不套用戰鬥资源的 90 秒額度上限，仍限制儲存 12 小時。小數秒保留、claim 重送不重新結算，瀏覽器提交時間戳不授權領取；見 [IDLE_STORAGE.md](IDLE_STORAGE.md)。

### 新裝備與洗鍊誤判修正（2026-10-07）

- 客戶端登入、掉落與整包存檔的詞綴整理統一使用 `canonicalAffixes`，與伺服器相容驗證共用規則。舊裝備上不屬於該部位允許池的詞綴（例如武器上的元寶掉率）會按既有伺服器規則清理，不再因其他詞綴名稱整理後仍保留不合法條目而被視為未授權洗鍊。合法重複詞綴保留；新增／改換既有詞綴仍須伺服器操作。
- 新掉落可以在首次自動存檔前強化；驗證從 +0 計入每級最低金幣／強化石成本，不再直接因新物品 enhance>0 拒絕。掉落戰力範圍、物品額度、地圖解鎖與未核發洗鍊計數的限制維持。
- `save-false-positives.test.mjs` 使用實際客戶端正規化函式驗證舊詞綴清理與服務端洗鍊後的正常存檔，並覆蓋新裝備首次存檔前連續強化、缺材料、偽造戰力與未授權詞綴／洗鍊計數。
