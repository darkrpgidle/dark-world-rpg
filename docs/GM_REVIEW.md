# GM 系統檢查與更新（2026-10-03）

## 已實裝

深色管理工作台、六區導覽、響應式手機介面、在線與存檔指標、異常原因統計、帳號／時間／原因篩選、逐筆差異展開與玩家跳轉。停權、還原、發放與存檔編輯延續既有 GM 權限；危險操作集中於折疊區及既有確認流程。

## 已確認並修正的問題

| 問題 | 修正 |
|---|---|
| 裝備欄依背包順序修改，可能改到未穿著物品 | 依啟用套裝的穿著 ID 與槽位查找 |
| 洗鍊編輯使用未被玩法讀取的欄位 | 使用 `reforgeCount`，相容舊 `reforgeLevel` |
| 更換目錄裝備可能保留舊特殊裝備身分 | 正規化目錄身分、地圖、品質與原始戰力 |
| 離線秒數編輯到線上獎勵計時 | 改用 `storedSeconds` |
| 快速切换帳號，舊請求覆蓋新選擇資料 | 請求世代與已讀取帳號檢查；還原確認綁定帳號 |
| GM 與玩家自動存檔互相覆蓋 | 版本樂觀鎖；提供登出並重讀操作 |
| 備份、修改、登出、操作紀錄分開執行，可能部分成功 | 編輯、發放、還原改成原子 D1 batch，附版本與操作回條條件 |
| 快照還原可回到舊離線領取標記 | 保留目前已消耗標記，重置額度與時鐘 |
| 發放資源可能把已超過十億的舊餘額減少 | 取消總額截斷，改驗證安全整數及加總溢位 |
| 過期 session 仍算在線、地圖欄位讀取舊名稱 | 排除過期 session，讀取目前 mapId／wave |
| 停權日期輸入混用 UTC 與本地時間；缺省模式可能永久停權 | 本地 datetime-local、臨時模式才解析日期，後端要求明確模式 |
| 管理資料可能被快取、一般 GM 操作混入系統拒絕紀錄 | 管理回應 no-store；異常紀錄独立頁面 |

## 建議下一步（依優先度）

1. **伺服器權威結算**：將戰鬥收益、隨機掉落、強化／洗鍊結果改由伺服器產生，採操作 ID、交易及重放保護。目前的存檔完整性限制仍容許範圍內偽造，不能因新增 GM 畫面就宣稱漏洞完全消失。戰力目前仍是最近存檔值，應抽出共享計算模組後由伺服器重新推導。
2. **管理操作可追溯性**：所有敏感寫入要求修改理由、保存有限欄位的前後差異，並拆分查閱／編輯／停權／重置權限。現有操作紀錄可查操作者與動作，但尚未全面提供修改前後差異；登出與停權路徑也可進一步統一交易紀錄。
3. **完整新版角色工作台**：集中昇華、天賦、寶石／插槽及異常加成的唯讀說明，再依版本規則建立安全編輯器。現有技能編輯支援職業、等級、技能點、一般技能槽；昇華只有展示，尚非完整編輯。
4. **成長後的營運能力**：玩家清單伺服器分頁、按實測資料量加查詢索引；離線發放透過一次性郵件回條。拒絕率高的帳號先查正常操作與時間，避免自動誤封。

## 驗證與限制

本次完整 `npm test`（包含正式 build）669 項通過；`npx tsc --noEmit` 通過；變更的管理、存檔與稽核檔案 lint 無錯誤與警告。新增 GM 測試包含原子備份／寫入／登出／紀錄、版本衝突零副作用、交易失敗回滾、穿著 ID 編輯、裝備身分正規化、稽核安全範圍與 GM 401／403 權限檢查。

尚未以正式 GM 帳號進行瀏覽器手動驗收；不把自動化測試當成所有操作已在正式資料上驗證。本次未對實際玩家執行停權、發放、修改或還原；未更動資料表。舊存檔中更深入的畸形欄位仍需個案處理，既有污染資料也不會自動回溯。
