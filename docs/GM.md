# 帳號、存檔與 GM 規格

## 帳號與 session

- 新帳號金幣、元寶均為 0。
- 刪除玩家時必須同步刪除／停用帳號憑證，舊名稱不可再登入舊存檔。
- 同帳號僅允許最新 session 寫入；舊視窗立即停止戰鬥與存檔。
- 被取代訊息：`此帳號已在新的登入環境開啟，本視窗已登出` 或 `偵測到較新的雲端存檔`。
- 存檔寫入採版本號／樂觀鎖，拒絕舊版覆蓋新版。
- 一般自動存檔在進度停止變動 5 秒後送出；持續戰鬥時最長每 30 秒排程一次（網路重試、未確認交易與操作互斥可能延後）。切換背景、通關等既有優先存檔仍立即排程；洗鍊／打孔由專用伺服器動作即時保存，不再額外催送整包存檔。

## GM 玩家修改（三頁）

1. 角色進度：輪迴、等級、技能、通關與首領解鎖。
2. 裝備：目前穿著槽位、品質、強化、洗鍊。
3. 資源：金幣、元寶、強化石、洗鍊石。

角色進度頁另可設定新版技能：職業、技能等級、三個一般主動技能槽與技能點上限。一般技能點依角色等級計算；GM 可為驗收角色設定最高 100 點，並使用「全技能滿級（測試用）」一次配置該職業 20 招 Lv.5。這項額外點數只可由 GM 存檔編輯寫入，普通自動存檔及技能操作不能自行提高。

驗收流程：在玩家清單選擇測試帳號（例如 `gmsf1`），先設定等級至少 Lv.50，再選職業並套用測試配置。切換職業會清空新版技能配置，避免跨職技能殘留。儲存仍會建立修改前快照並使測試帳號登出。

### 工作台

入口沿用遊戲內 GM 管理，提供監控總覽、異常存檔、玩家管理、存檔編輯、存檔還原、資源發放六個區域。桌面採側欄及獨立內容捲動；手機改為橫向導覽。總覽每 30 秒更新；異常紀錄提供手動更新、篩選及分頁。

「異常存檔」讀取既有 `gm_action_logs` 的 `save_integrity_rejected`，可依帳號、24 小時／7 天／全部、原因篩選。每頁 25 筆，顯示拒絕原因、帳號、時間、有限欄位的雲端原值與提交值，並可跳到玩家管理。舊紀錄沒有差異資料；物品內容變動也可能不改變筆數。拒絕記錄不等於作弊判決，不自動停權；持久紀錄每帳號每分鐘最多一筆。

### 修改與還原規則

- 存檔編輯選單可選目前 GM 自己；僅編輯器使用 `includeSelf=1`，其他管理玩家清單仍排除 GM。讀取／修改允許一般玩家與目前 GM 自己，其他 GM 仍受保護；刪除、停權等保護不變。
- GM 管理開啟期間暫停本視窗普通自動存檔，關閉後恢復；已送出請求仍受版本檢查保護。修改自己亦會原子備份、登出全部該帳號 sessions 及記錄操作，需重新登入載入完整修改；其他登入環境造成版本變更仍回傳 409。

- 裝備按目前啟用套裝的穿著 ID 對應槽位，不按背包順序。卸下僅解除目前套裝穿著，不刪除物品。更換裝備會同步目錄身分、地圖與洗鍊欄位。
- 離線掛機秒數編輯 `storedSeconds`（上限 43200）；`idleSeconds` 是另一個線上計時欄位。
- 新版技能配置延續伺服器正規化。GM 昇華編輯依轉生次數開放 1～5 階段，保留合法既有選擇；第二、三轉不可重複，第五轉固定奧義。調低轉生移除超出階段選擇，切換職業清空不相容選擇。未選完以 selectionOpen 儲存，玩家重新登入完成選擇；選滿後直接啟用。GM 寫入同步兩個轉生計數並清除待執行輪迴回條，避免誤觸正常輪迴重置。
- 讀取存檔帶入版本。切換玩家會使舊請求失效，提交版本衝突回傳 409，要求重新讀取。
- 玩家自動存檔會持續改變版本；可先用「登出玩家並重新讀取」取得穩定資料。儲存成功亦會使目標玩家登出。
- 編輯、發放、快照還原以原子 D1 batch 完成版本檢查、修改前快照、寫入、登出及 GM 操作紀錄；寫入未成功不得產生後續登出與成功紀錄。
- 還原沿用目前伺服器已消耗的離線領取標記，清空普通收益額度並更新伺服器時鐘，避免舊快照重放離線收益。
- 資源發放限安全整數，檢查加總溢位；不因既有餘額高於單次發放上限而把餘額削減。
- 各管理端點由伺服器核驗 GM 身分，管理回應不快取；過期 session 不計入在線玩家。

已修正問題、驗證範圍與後續方向見 [GM_REVIEW.md](GM_REVIEW.md)。

## 管理能力

- 大清洗：只保留明確 allowlist（現行 GM：`gm4d`）；执行前必须显示数量并建立可恢复快照。
- 停權：狀態、原因、開始／到期時間、操作者；登入時顯示原因，不刪存檔。
- 還原：只能選擇既有快照；還原前再建立當前快照；所有操作寫 audit log。
- GM UI 在手機版必須可見，但功能仍由伺服器角色驗證，不能只靠前端隱藏。

## 每日任務時間

個人首領於每日 00:00 重置。正式環境必須固定時區並以伺服器日期鍵判定，避免客户端改時間。

- 今日獵殺 500 隻的獎勵以台北日期由服務端一次領取並記錄領取日期；舊存檔今日已領標記相容。擊殺數仍沿用現有客戶端戰鬥計數，待正式戰鬥服務端權威接線。

一般存檔與資源防作弊的檢查、相容性與限制見 [SAVE_INTEGRITY.md](SAVE_INTEGRITY.md)。每日獵殺領取以雲端已存入的當日擊殺數判斷，不接受領取請求自行增加進度。

## 指定帳號刪除

GM 管理 → 玩家管理 → 刪除帳號。要求輸入完整帳號名稱與刪除原因，伺服器再次核驗 GM 身分及目標帳號；所有 GM 帳號與自己均受保護。原子交易建立刪除前快照、記錄帳號名稱／原因／操作者，再刪除所有目標 sessions、目前存檔、輪迴獎勵資格及登入帳號。歷史快照、死亡統計、全域歷史備份與 GM 紀錄保留舊帳號 ID；一般還原功能不會重建已刪帳號。同名重新註冊產生新 ID，不能繼承舊資格或快照。此功能沒有一鍵撤銷。

## GM 純文字郵件

玩家管理 → 寄送郵件，標題 80 字、內容 2000 字，保留 7 天，每帳號最多 50 封期間內 GM 訊息；滿額拒絕寄送，不丟掉原有信件。使用既有 gm_action_logs 作為伺服器郵件來源與寄送紀錄（gm_mail），已讀回條為 gm_mail_read。登入後每 30 秒讀取自己的郵件，未讀計入郵箱徽章；已讀跨裝置保存。與獎勵郵件分開，不修改玩家存檔、不強制登出、不附帶資源。寄送以 GM＋requestId 的單一條件 INSERT 防重複；重試沿用 ID，修改內容換 ID。訊息只以純文字渲染，伺服器限制收件帳號及讀取範圍。歷史記錄保留供 GM 查核，信箱只顯示 7 天內資料；不會把舊帳號郵件轉給同名新帳號。

## 登入安全（2026-10-03）

建立登入採單次原子交易替換 sessions，最後完成的登入保留，舊 token 不再能通過存檔寫入；插入失敗整筆回滾。交易再次檢查帳號仍存在且未停權。既有登入仍可使用，下一次登入會清除同帳號可能殘留的多筆 session。

登入／註冊由 auth_rate_limits 持久共用計數，先限流再做密碼運算；成功與失敗嘗試皆計數。固定時間窗預設：同帳號登入 10 次／15 分鐘，同來源登入 60 次／5 分鐘，同來源註冊 5 次／小時；另有全站 300 次／分鐘。來源採平台 CF-Connecting-IP，不採用可偽造的 X-Forwarded-For；未提供來源時使用共同備援桶。計數鍵保存來源／帳號雜湊，不存明文 IP 或密碼。超限回 429 與 Retry-After，前端顯示等待時間；共用計數不可用則回 503，不悄悄放行。過期計數清除，正常開著遊戲的認證查詢不計入登入嘗試。新增資料表透過 0010 migration 建立，不更動既有帳號／角色表。

## 深淵王獎勵稽核

新版四張world_boss資料表保存有效傷害事件、每期完成回條／前三名、獎勵郵件與領取回條。GM文字郵件與獎勵來源分開，正常玩家不能自製核發來源。新郵件使伺服器存檔版本／adminRevision更新，但不刪session；舊客户端同步會收到正規化完整存檔並重新載入。領取回條獨立於角色快照，還原後會將已領郵件恢復為已領狀態，避免重領。
