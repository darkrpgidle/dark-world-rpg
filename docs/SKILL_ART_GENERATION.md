# 暗黑世界：技能影格生圖與播放製作方式

更新日期：2026-10-01。依目前專案程式及已確認的美術要求整理。

本文件記錄可重用的製作流程。提示詞是整理後的範本，並非歷次生圖的原始紀錄。技能數值以遊戲程式為準；播放規格另見 `VFX.md`，技能規則見 `SKILLS.md`。

## 1. 製作架構

採用「生成連續影格 → 整理 Sprite Sheet／Atlas → 透明 WebP → WebGL 播放」的方式。

- 生圖提供巨獸、武器、斬擊、裂縫等主要美術與動作影格。
- WebGL 讀取圖集中的來源矩形，依時間播放影格，另可繪製光環等輔助效果。WebGL 本身不負責生成這些美術圖片。
- Canvas 2D 作為備援，同一套來源影格、位置與命中時序應保持一致。
- 畫面震動由 CSS／Web Animations 等顯示層處理；傷害文字由 DOM 顯示。
- 顯示層接收戰鬥結果，不自行計算、增加或重複派發傷害。

這是目前戰士部分技能的架構，不能假設所有職業與技能都已改用 WebGL。

## 2. 生圖之前先確認

| 項目 | 必須定義的內容 |
|---|---|
| 技能內容 | 主動／奧義、實際命中次數、昇華追加效果、命中或落空分支 |
| 視覺主體 | 人物或巨獸外觀、武器形狀、主色、能量與碎片風格 |
| 動作 | 蓄力、揮擊、命中、餘波、消散；每段對應哪些影格 |
| 時間 | 每格停留時間、命中格、動畫完成時間；不必每格等速 |
| 定位 | 玩家／敵人錨點或戰鬥區置中，固定尺寸或允許移動 |
| 範圍 | 是否為場外飛入、全場覆蓋、光芒與碎屑越界的特殊技能 |
| 回饋 | 震動幅度、傷害字尺寸、光環、閃光、減少動態效果版本 |

規格應隨遊戲實際技能更新。改動命中次數、昇華方式或施放條件時，也要一起檢查影格與事件對應。

## 3. 生圖與整理流程

1. 先用一張參考圖確定主體外觀、構圖、武器比例和配色。
2. 排出逐格分鏡，再生成連續動作圖集；重製時以既有主體／圖集作為參考。
3. 各格維持相同鏡頭、主體比例、畫布與定位；避免每格重新構圖造成跳動。
4. 檢查動作連續性、手部握劍、武器形狀、命中位置及消散過程。若不一致，修正有問題的影格或整組重製。
5. 移除文字、浮水印、格線與底色，驗證檔案有真正的透明 Alpha；棋盤圖案不等於透明。
6. 將影格排成圖集，順序固定為每列由左至右、再由上至下。記錄格數、列欄、像素尺寸及來源矩形。
7. 輸出透明 WebP，驗證透明邊緣、尺寸、細節與檔案大小。
8. 接入播放器，設定各格時間、錨點、命中與完成回呼，最後在遊戲中驗收。

現有 `scripts/optimize-static-images.py` 可將 PNG 轉為 WebP並檢查尺寸及 Alpha 不變；它會掃描整個 `public` 並在成功後刪除原 PNG。製作單一技能時應限定處理新素材，避免不必要的全目錄異動。

## 4. 可重用生圖提示範本

```text
為暗黑奇幻遊戲製作「{技能名稱}」的連續技能動畫圖集。
參考提供的角色／技能圖，保持主體外觀、武器、配色與畫風一致。
透明背景，無文字、無標籤、無格線、無浮水印。
共 {格數} 格，排列 {欄數} 欄 × {列數} 列，按左至右、上至下播放。
各格相同畫布、相同視角、相同主體比例與中心位置。
主體：{角色或巨獸、武器、材質、主色與能量風格}。
逐格動作：{每格或分段列出蓄力、揮擊、命中與消散}。
命中畫面為第 {命中格} 格，保留武器輪廓與主體辨識度。
揮擊前有可讀的蓄勢，揮擊快速有力量，命中後接衝擊波與餘燼消散。
主體保持定位；動作由姿勢、武器與特效改變呈現。
所有格子的特效不得串入相鄰格；保留裁切安全邊界。
```

提示詞中的快速揮擊，仍須由播放器的每格時間落實。大招越出戰鬥區的效果須由遊戲圖層支援，不能靠圖集畫到相鄰格實現。

### 泰坦斷界斬分鏡與節奏

主體是泰坦巨獸的虛影，持巨劍向前斬開空間。主斬影格固定置中、固定尺寸，不以平移影格營造揮擊；後續追斬貼合敵人位置。

| 影格（由 1 起算） | 節奏／回饋 |
|---|---|
| 1～11 | 每格 120ms；凝聚虛影、舉劍蓄勢 |
| 12～16 | 每格 45ms；快速揮劍、斬裂空間 |
| 第 12 格開始 | 1320ms；輕震起手 |
| 第 15 格開始 | 1455ms；命中顯示回呼、整個戰鬥區強震 450ms、特大金紅傷害字與擴散光環 |
| 17～20 | 每格 120ms；衝擊、碎屑、裂縫消散 |
| 第 20 格開始 | 1905ms；餘震 |

「12～16 格加快」指這幾格的揮擊速度，總格數仍是 20 格。電腦震動最大 16px，手機 9px；命中才震動。主傷害字持續 1.5 秒。

傷害文字依真正播放進度顯示，不從施放時另設固定延遲，以免素材慢載入造成不同步。此處延後的是文字顯示，戰鬥扣血仍由戰鬥結算處理。

## 6. 定位、越界與合成

- 依玩家／敵人框即時 `getBoundingClientRect()` 換算座標，手機與電腦共用比例定位，視窗改變時重新計算。
- 保留影格長寬比；來源矩形內縮約 1px，避免線性取樣讀到相鄰格。
- WebGL 與 Canvas 2D 的上下方向及取格座標必須一致。
- 泰坦使用一般透明合成，避免加亮合成讓巨劍與裂縫過曝；其他技能按美術需求選擇。
- 產品允許奧義或指定大型技能從場外飛入、覆蓋戰鬥區，並讓邊緣光芒／碎屑越界消散。實作前須確認容器裁切、特效層範圍與其他 UI 的遮擋。
- 目前泰坦的定位仍以戰鬥框可用區域為界；允許越界的設計要求，不代表現有播放器已實現所有越界效果。

## 7. 戰鬥事件與清理

- 三職奧義能量滿 100 時採最高施放順位；施放期間雙方攻擊暫停，動畫完成後恢復。
- 暫停由戰鬥狀態控制，不用忙等或阻塞 JavaScript 執行緒。
- 奧義與追加效果不顯示「技能發動」提示橫幅，保留特效與傷害文字。
- 昇華追斬依實際追加事件觸發，不因圖集有三組就自行增加三次傷害。
- 落空使用對應揮擊／淡出，不播放成功命中的強震。
- 減少動態效果使用靜態命中格與傷害文字，取消強震與放大動畫。
- 完成、載入失敗、戰鬥切換或元件卸載均須妥善清理及釋放動畫鎖；正常戰鬥結束時移除特效，不保留多個循環或殘留 Canvas。

## 8. 驗收清單

- [ ] 各格主體、武器、視角、尺寸與定位一致，動作連續。
- [ ] 透明背景正確，無棋盤底、文字、黑白邊或相鄰格漏光。
- [ ] 蓄力可讀，揮擊迅速，命中、震動及傷害文字同步。
- [ ] 主斬與昇華追斬符合遊戲實際命中事件與數值。
- [ ] 手機／電腦不拉伸、不遮擋必要 UI；越界效果符合指定範圍。
- [ ] WebGL、Canvas 備援、落空、慢載入與減少動態效果均可正常結束。
- [ ] 奧義完成後雙方攻擊恢復，切換戰鬥沒有殘留節點或動畫鎖。
